# Turn-depth arm: first run, stopped early at the floor (2026-07-27)

Result: **no measurement**. Not a null about chameleon -- the instrument had no
range on these fixtures, so the run could not have produced a signal in either
direction. Stopped at 8 of 12 cells, $10.56.

## What was being asked

Every other scorer reads the final tree, which answers "was the end state good"
and cannot answer "did guidance hold". Those come apart: a model that infers the
repo's conventions at turn 2 and drifts off them by turn 12 still lands a
passable diff, and a whole-tree score calls that a win.

That distinction is the one the competitive picture turns on. The claim
separating per-edit injection from a conventions line in CLAUDE.md is that
re-delivering guidance before every edit resists decay a once-per-session
delivery cannot. So: ask for six sibling files in a fixed order, lint each as
authored, compare the first half of authoring order against the second.
Positive decay = conformance degraded with depth.

## What happened

Every scored cell, both arms, both languages: zero violations in every authored
file.

| task | arm | cells | files/cell | early | late | decay |
|---|---|---|---|---|---|---|
| ts-six-components | off | 3 | 5 | 0.0 | 0.0 | 0.0 |
| ts-six-components | shadow | 3 | 5 | 0.0 | 0.0 | 0.0 |
| rails-six-services | off | 2 | 6 | 0.0 | 0.0 | 0.0 |

Flat decay here does not mean conformance held. It means the task tripped no
rules at all, with the plugin off or on. Those are the same number and opposite
conclusions, which is why the scorer now emits `depth_floor` rather than letting
a scoreboard read 0.0 as a win.

## Why it was stopped at 8 cells

The four unrun cells were all `shadow`. Their `off` counterparts already scored
zero violations, and chameleon can only reduce violations, never add them -- so
no possible result from those cells differs from what was already recorded.
Spending the remaining ~$6 would have bought four more zeros whose value was
determined in advance. The run was killed rather than completed.

## Two defects this run exposed

**The archetype was passed in the wrong shape.** `get_pattern_context` nests the
name one level deeper than it reads: `data.archetype` is an envelope whose own
`.archetype` is the string. Passing the envelope made `lint_file` stub with
"archetype must be a string", which the scorer read as "nothing to lint" and
reported as unscored. The first six cells produced no depth signal at all, for
what looked like a data problem and was a type error. The unit tests missed it
because the mock modelled the same flat shape the scorer wrongly assumed -- mock
and code agreed with each other and not with the API.

**Fixture prep could not run from a path with spaces.** `fixtures.py`
interpolated an unquoted path into `git clone --bare . <dest>`, so every eval and
journey run died in prep with "Too many arguments" once the repo moved under a
directory containing a space. Fixed with `shlex.quote` and pinned by a test that
runs the fixture under a spaces-containing root.

## What would make this answerable

The committed `eff_ts` / `eff_rails` fixtures are too permissive: straightforward
new-file authoring conforms to them trivially, so there is no violation for decay
to show up in. Measuring turn-depth needs a fixture whose conventions a drifting
model would actually break -- a required base class, a mandated import form, a
naming rule with teeth -- so that early-file and late-file conformance can differ
at all. Until then the arm is built and tested but unusable, and no claim about
guidance surviving session depth should cite it.

Secondary limit worth carrying forward: authoring landed in a tight burst near
the end of each session (TS writes at turns 15-19, one Rails cell at turn 38).
The gap between "early" and "late" is a few turns, not the turn-1-to-turn-10
spread the arm's framing implies, so even a working fixture would measure decay
across a burst rather than across a session.

## Reproduce
